# 浏览器页面使用说明

这个目录放的是 ResearchPilot 的网页部分，也就是浏览器里能看见的页面、按钮和表格。
它根据前端规格文档制作，页面用 Vue 编写。

**当前默认是演示模式，还没有连接项目的 Python 程序和数据库。**
你可以体验页面和已有结果，但不能把演示中的收藏、分析进度当成真实后台操作。

## 1. 怎样打开页面

终端先进入项目的 `web` 目录：

```bash
cd web
npm install
npm run dev
```

- `npm install`：安装网页需要的软件包。
- `npm run dev`：启动本地网页。

然后打开终端显示的地址，通常是 `http://127.0.0.1:5173`。
不要直接双击 `index.html`，那样不能正常运行整个项目。

建议使用 Node.js 22.6 或以上，因为项目的部分检查命令需要这个版本支持。

## 2. 演示模式可以做什么

页面顶部会一直标注“演示模式”。演示材料来自项目此前导出的论文、分析和综述文件。

| 你操作什么 | 实际会发生什么 |
| --- | --- |
| 搜“深度估计”或“单光子” | 在准备好的论文样本里筛选，不是实时联网搜论文 |
| 收藏论文 | 记录在当前浏览器里，不写入 PostgreSQL |
| 选择本地 PDF | 可以预览；请求解析时会提示需要后端 |
| 查看分析 | 加载已有分析样本，不重新请求模型 |
| 生成演示综述 | 加载已有报告；当前报告只对应单光子相关主题 |
| 查看任务 | 展示模拟的进度变化，不是 Python 真正工作进度 |
| 向 Agent 提问 | 提示模型未连接，并保留你的问题 |
| 点击引用 | 查看样本原文和归属；没有真实位置数据的部分会显示待核验 |

浏览器换了、清除了网站数据，演示收藏等记录可能就没有了。
在终端中新生成的结果，也不会自动更新这里的样本文件 `src/data/seed.json`。

## 3. 每个页面用来做什么

| 页面 | 主要用途 |
| --- | --- |
| 工作台 | 看文献数量、最近文献，进入搜索、分析和综述 |
| 文献检索 | 输入主题、筛选年份、读摘要、选择收藏 |
| 我的文献库 | 查找已收藏论文，区分有没有全文、有没有分析 |
| 论文详情 | 查看资料、全文、证据片段和已有分析 |
| 科研 Agent | 提问、看回答和工具执行过程、点击引用 |
| 论文分析 | 选一篇已有全文的论文，看五类分析并下载 JSON |
| 文献综述 | 选 2–5 篇已分析论文，看比较表和综述、下载文件 |
| 任务中心 | 看哪些工作在排队、进行中、完成或失败 |
| 设置 | 切换数据模式、查看连接状态、调整每页条数和配色 |

“已收藏”“有全文”“已分析”是三个不同状态。例如，一篇论文可以已经收藏，但还没有 PDF，因而不能做全文分析。

## 4. 怎样看引用

看到 `E21` 或 `P2:E21` 时，可以点击它。
右侧会打开一个面板，显示对应论文、原文、页码和来源。

`P2:E21` 表示“论文 2 的原文片段 E21”。如果查询后发现 E21 属于另一篇论文，页面会报归属错误，不当成有效来源。

“位置已核验”只说明编号、原文和位置能对上，不表示该段文字一定充分支持模型写出的结论。

## 5. PDF 预览有什么限制

当前使用浏览器自带的 PDF 阅读器。可以预览你选的本地文件，并尝试跳到指定页码。

- 没有原始 PDF 时，不会凭空显示一个预览。
- 需要你确认文件与当前论文一致，再提交上传。
- 真正解析、保存原文，需要接好后端。
- 目前不能精准高亮某一句被引用的文字；能翻到某页，不等于已经定位到原句。

## 6. 为什么不能直接切到“真实 API”就用

“真实 API”表示：页面要向 Python 后端发送要求，获取真实结果。
但项目目前还没有对应的网页后端入口，所以切换模式本身不会自动把它开发出来。

以后后端接口做好后，可在设置页切到真实模式。
开发时也可以在 **web 目录**新建 `.env.local`，参照同目录的 `.env.example`：

```dotenv
VITE_API_BASE_URL=/api/v1
VITE_DATA_MODE=api
```

这里仅填写公开的网页设置，**不要填模型密钥、数据库地址或密码**。
注意：项目根目录 `.env` 是 Python 使用的文件；`web/.env.local` 是网页使用的文件，不是同一份配置。

如果浏览器已经记住了模式，优先在设置页修改。
开发配置目前会把 `/api` 请求转交给 `http://127.0.0.1:8000`，后续需与实际后端地址一致。
详细约定见 [接口说明](API_CONTRACT.md)。

## 7. 任务和错误怎样显示

真正接上后端后，解析、分析和综述应该先拿到一个任务编号，再查询进度。
网页已经写好了定期查询的逻辑：完成后停止查询，连续失败后暂停，离开当前页仍可保留活跃任务编号。

但它只负责“查看进度”，不负责执行 Python 工作。真正执行和长期保存任务状态的部分还需要开发。
目前也没有对应的后端取消、重跑接口，所以页面不提供假装可用的取消功能。

模型文本按普通文字和引用编号安全显示，不执行其中的 HTML 指令。
复杂的 Markdown 排版目前没有完整支持；综述则直接按背景、方法、比较等栏目排版。

## 8. 怎样检查网页代码

```bash
npm run build
npm test
npm run test:render
npm run test:data
```

分别用于生成网页文件、检查小工具、检查页面能否生成，以及用样本检查数据操作。
`npm run build` 会把可部署文件放到 `dist/`。
这些检查不等于实际打开浏览器、上传 PDF、连接数据库都成功，详见 [测试说明](../docs/TESTING.md)。

如需把页面部署到服务器，服务器需要支持：非 `/api` 的页面地址回到 `index.html`，否则直接打开论文详情地址时可能报找不到页面。

## 9. 改页面时该找哪些文件

| 目录 | 用途 |
| --- | --- |
| `src/views/` | 每个功能页面 |
| `src/components/` | 多个页面共用的小部件，例如引用、侧栏和 PDF 阅读区 |
| `src/layouts/` | 左侧导航、顶部栏等外框 |
| `src/styles/` | 字号、颜色、间距和不同屏幕宽度的布局 |
| `src/api/index.ts` | 页面向后端提交操作的统一入口 |
| `src/api/demo.ts` | 演示模式怎样返回样本 |
| `src/data/seed.json` | 演示样本数据，已去掉本地 PDF 绝对路径 |
| `src/stores/` | 多页面共用的引用面板和任务状态 |
| `src/router/` | 规定哪个网页地址打开哪个页面 |
| `src/types/` | 约定论文、分析、任务等数据应有哪些字段 |
| `scripts/`、`tests/` | 检查网页代码和演示流程 |

更多项目背景见 [项目说明](../docs/PROJECT_GUIDE.md)，逐个按钮的 Python 对应关系见 [功能对照](../docs/FEATURE_MAP.md)。

## 当前检索来源

文献检索仅使用 arXiv，已移除 OpenAlex/Google Scholar 下拉选项与引用量排序。实时检索需要设置为“真实 API”；支持年份、分页和相关性/最新提交/最近更新排序。收藏后可在详情页获取 arXiv PDF。演示模式仅展示明确标注的示例记录。

## 页面上的 AI 分析

单篇分析已接通 API。在“论文分析”选择有全文的论文，点击开始，等待后台任务完成后查看结果、引用和历史。也可从论文详情点击“分析论文”。模型配置沿用服务端 .env，页面不传 API Key。结果可下载 JSON；原文更新后的旧报告会标注为历史分析。

## 多篇比较与综述

已接通真实 API。在“文献综述”选择 2–5 篇已有有效分析的论文，先查看比较矩阵，再填写主题生成综述。后台固定本次分析版本并核验跨论文引用；完成后可以下载 CSV、JSON、Markdown。旧报告可从任务中心重新打开，原文更新后会标为历史报告。

## 分批分析与继续进度

现在默认按顺序分析全文，每批最多 2 个片段。每批通过原文核验后保存；失败时只重试当前批次。停止后可以点“继续未完成批次”，刷新页面也会恢复最近的未完成任务。全部完成后合并报告，不再额外调用模型。

全文可能需要更多请求、时间和费用；只想试跑时可以选“抽样分批分析”。“重新分析”会从头请求模型。完整的通俗说明见[分批分析使用说明](../docs/BATCH_ANALYSIS_GUIDE.md)。
