# P2 第五步：执行内独立评审和评审版本关联

依赖固定角色配置、既有逐结论评审器和固定分析选择。新增执行内的逐篇确认入口，并把明确选择的完整评审关联到新分支、覆盖检查及综述。不是新建评审策略，不改分析或模型标签，也不代表 P2、自主研究或评审准确率已验收。

## 行为与边界

- 点击“查看或刷新评审版本”只读元数据，显示固定模型、超时、SDK额外重试和各分析的结论数量。打开页面不自动发起评审或覆盖调用。
- 每次明确确认一篇分析，复用既有 `claim_reviews.start_review`，强制使用执行根任务的 Claim Review 角色清单，独立于 Analysis 调用。没有固定配置的历史执行拒绝，不改用当前默认配置。新任务关联执行父任务、原分析任务及运行版本；复用已有任务不重写其历史归属。
- 每条结论单独评审，SDK有限重试和单次超时沿用原配置；每篇实际次数取决于结论数、已完成项和失败情况。这是既有手动评审路径，没有新增跨论文自动调度、项目总调用预算或整个阶段的绝对期限。未知 token/费用仍为空。原请求继续只处理未完成项，不重跑分析。
- 选择每篇至多一个当前、完整成功的评审。支持、矛盾、证据不足等标签均可关联，不以支持率决定通过。旧协议复用数量明确显示；关联不冒称新协议重新评审，也不生成或覆盖人工裁定。
- 明确确认后另存评审选择及新执行分支，仅关联本次选择的评审；未选项作为未评审，原分支的全部历史保留。评审、分析、原文归属及指纹在后端校验；后续覆盖和报告前后再次核验被关联内容，检查点改变时拒绝混用，历史覆盖报告仍可查看并标为失效；重复或外来分析/评审、失效材料和未完成评审拒绝。可选其他模型的历史完整评审，其来源任务和版本保留；从本执行发起的评审使用原执行配置。
- 确认问题后发起独立覆盖任务，初值为原计划问题，可编辑。覆盖输入含所选评审的真实辅助判断，未选分析明确未评审；不按标签直接证明覆盖充分。失败后相同输入复用分支并继续覆盖。问题或评审选择变化另建分支。
- 后续比较/综述关联该分支的评审编号与来源任务；原分析、原报告不修改。页面切换整组执行结果到新分支，可查看评审和原文。模型调用成功、字面校验和语义正确分别验收。

选择记录复用 PostgreSQL 不可变产物表，任务/执行沿用 SQLite，不新增数据库迁移。不改评测授权，不提交或推送代码。

## 本机验收

1. 重启服务，使用含新代码清单的新研究计划；固定分析可复用已有结果。完成补读/补充材料选择或普通文献库执行。
2. 在执行结果中点击“查看或刷新评审版本”，核对模型、结论数与实际分析 ID。此时不得发起模型请求。
3. 确认一篇分析的评审，等待逐条核验保存，打开“核对评审理由与原文”人工检查。失败后继续原评审，确认不重跑分析，且仍使用原角色模型。
4. 选择完整评审版本和检查问题，点击“确认评审版本并重新检查覆盖”。新分支仅关联所选版本；原报告及评审历史保留。包含“矛盾”的评审也可以进入，标签不被强制改写。
5. 核对新覆盖报告及后续综述的实际评审 ID、阅读范围和分析 ID。字面核验通过不能替代人工语义判断。
