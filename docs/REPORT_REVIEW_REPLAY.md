# 综述独立审查、原协议回放与 Evolution 交接

本次依据实际 HEAD `367060413dc1978734522f037c826bf4f9d88984` 的实现补齐可追溯、可复现和可评测的前置能力。ResearchPilot 的目标是围绕通用科研问题完成规划、检索或文献库选文、阅读、比较和有原文依据的报告。现有 Research/Analysis/Review 是逻辑职责，Evolution 是离线开发工具循环；本次沿用这些模块，不增加 Agent 框架或定时研究。

## 实际变化

- 综述生成与 CLI 共用 `prepare_review_request` / `invoke_review_request`。调用前保存真实 Prompt、Schema、结构化方式、完整输入、允许引用、写作规则及稳定哈希；成功报告携带同一请求，失败任务仍保存该请求和原有诊断。引用门槛保持原规则，跨论文比较主题句须有至少两篇来源。
- 新根任务的运行清单增加独立 `report_review` 角色。主题句和每个解释段落分别审查，提供所引用片段的完整上下文与原文编号，保留待验证方向的表述强度和实际阅读范围。程序取回引文、页码与片段内字符位置，网页无页码时保持未知。总体 supported 与逐证据相反的判断单独诊断，不改标签、不改原报告。
- 原协议回放恢复报告原 `review` 角色，使用相同输入、Prompt、`ReviewDraft`、结构化方式、引用范围及运行配置。它不是通用问答替身。不承诺模型输出逐字一致；原文快照固定，第三方模型漂移和随机性仍存在。旧报告缺少实际请求或原版本不可用时明确停止，不补采当前配置冒充历史。
- 检查请求和每次结果保存在既有 PostgreSQL `CoverageArtifact` 不可变仓库；租约、预算和逐次检查点使用独立 SQLite。显式续跑沿用原预算/期限/角色，成功项不重发，失败历史另存；未知中断请求不自动重发。次数统计指程序请求，供应方内部重试及未知 token/费用不伪报计费。
- 验收记录可选绑定 `report_review_id`、`report_replay_id`，核对报告归属、材料指纹和完整检查状态。程序链路通过、模型语义判断及人工声明分开保存。检查任务继承交互、根任务和父任务，可从原规划任务的 trace 查看。

新入口在综述正文下方，计划报告和独立综述页面共用；任务中心可返回原报告。界面提供调用次数/总时限、历史、失败继续和真实原文。默认不自动启动检查。

## 接口与本机验收

先按 [P0 执行溯源](P0_EXECUTION_PROVENANCE.md) 初始化已有版本及产物表，启用 `RESEARCH_RUNTIME_PINNING=true`，创建新根计划。Codex 固定版本要求明确 `CODEX_MODEL`。本次没有数据库结构迁移，不更新旧任务的配置。

1. 创建并保存计划，执行检索选文或使用已有文献库；完成分析和可选单篇评审。
2. 确认问题、维度和阅读范围，生成综述并下载 Markdown/JSON/CSV。
3. 在综述下方启动“独立审查”，查看每个主题句、解释段落、理由与完整原文；失败时在原预算内继续。
4. 启动“按原协议回放”，核对原请求哈希和独立结果。切换全局默认模型后，旧报告仍恢复原配置；新根任务使用新默认值。
5. 调用计划执行的 `acceptance/inspect`，传入 `report_id`、独立审查结果 `report_review_id` 和回放结果 `report_replay_id`，可同时传 `coverage_id`。再按原验收入口保存人工声明，默认全部“未检查”。
6. 对原规划任务读取 `/api/v1/tasks/{task_id}/trace`，核对计划修订 → 检索/文献库执行 → 分析/单篇评审 → 计划报告 → 综述 → 独立审查/回放的父子关系、固定产物和运行编号。

接口：`POST /api/v1/reviews/{id}/checks`，body 为 `{kind: "independent_review" | "original_replay", max_calls: 100, total_seconds: 1800}`。继续时加 `resume_request_id`，预算字段以已保存值为准。`GET /reviews/{id}/checks` 列出任务；`GET /reviews/{id}/checks/{result_id}` 返回不可变结果并标记来源是否变化。

## 实际问题交给 Evolution

在检查结果中选择交接，明确材料离线用途授权、授权人及验收要求。后端只接受已保存的失败、非 supported 或总体/逐证据冲突项；没有实际问题时拒绝制造任务。该授权独立于普通研究执行和业务验收，不填人工 gold。

交接接口 `POST /api/v1/evaluation/reports/{id}/handoff` 沿用评测路由的本机访问限制。材料限定 development，保存来源结果指纹、原请求、原文和授权。控制器的逐例 `read_feedback` 可读取真实问题；回答模型与辅助评审看不到人工要求。原问答数据包序列化与输入指纹继续兼容。

离线实验沿用现有预算、技能、候选和辅助评审循环，基线直接使用原综述 Prompt/输入/Schema；候选只增加通用指令和技能，不调整引用校验。实验的实际超时收紧和零程序重试按现有演化合同记录。辅助语义意见不是人工答案，候选输出没有增益时保留基线。

```powershell
# 仅准备，不发模型请求；使用与交接仓库相同的已授权测试配置。
.venv/Scripts/python.exe -X utf8 manage_research_evolution.py report-experiment <handoff_artifact_id>

# 实际执行（显式调用授权）；预算和期限持久化，恢复不归零。
.venv/Scripts/python.exe -X utf8 manage_research_evolution.py report-experiment <handoff_artifact_id> --confirm-model-calls
```

本次接通可手动发起的离线实验，不扩大在线自动化、启用排程或发布候选。真实完整流程、人工复核和独立材料收益验证完成后，再决定后续自动化范围。
