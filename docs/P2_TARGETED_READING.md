# P2 第二步：人工确认的问题导向补读

本步在固定的覆盖报告上接通“定位原文 → 确认片段与预算 → 补读 → 保存新分析 → 显式重新检查覆盖”。依赖 P0 运行配置固定、P1 文献库及版本核验、P2 覆盖报告。外部补检索与自动多轮研究尚未接入；程序校验和受控测试不代表语义判断已完成人工验收。

## 行为与边界

- 仅执行 `read_existing` 建议列明的本轮论文。定位不调用模型，使用研究问题、建议目标及用户定位词，对原分析对应文档的真实片段作关键词排序。最多展示40个候选，显示 E 编号、完整原文、页码、章节提示和已读/未读。排序不是语义相关性证明；可填写英文术语重新定位，已读片段也可重核。
- 人工选择1–12个片段，每次一篇论文、一轮；发送完整片段，不截断原文。片段超过原根任务的每批字符预算时拒绝，不悄悄跳过。文档 ID、哈希、原文/位置及原分析都固定，绝不读取最新文档替代原版本。
- 沿用原根任务 Analysis 角色的模型、Prompt、Schema、连接方式与分批配置，实际请求加入确认的问题和缺口。逐批核验、保存；最终按既有确定性合并规则保留旧结论并追加新结论。新分析标为 `supplemental`，显示旧、新阅读范围并集，保存 `base_analysis_id`、`supplemental_analysis` 与来源覆盖报告。不是重新阅读全文，也不保证一定发现新证据。
- 原分析、评审、综述与覆盖报告不覆盖。补读成功不意味着问题已回答；新结论尚未经独立评审，可以在新分析页显式发起辅助评审。
- 点击“用新分析重新检查覆盖”才建立新执行分支并发起覆盖检查，使用原覆盖问题及其余论文的原分析。改变分析的论文不继承旧评审。该覆盖调用是单独任务，不包含在补读预算内。原执行和原覆盖报告保留；页面切换整组执行结果到新分支，分析链接、覆盖检查及后续比较/综述使用同一分析选择；也可从计划执行历史返回旧分支。
- 每个派生分支最多补读一轮，不自动扩展到下一轮。需要进一步研究时先人工核对并另建计划。本限制针对单条分支；用户另行确认的新补读请求有自己的范围与预算，不构成系统级总预算。

## 预算、恢复与停止

默认最多8次模型调用、600秒执行期限；允许1–24次、10–1800秒。每批无自动额外重试，SDK 重试固定为0。每一次实际模型调用前原子预扣预算，分析、引用候选选择修复及失败调用都计入；超时/崩溃期间未确认是否送达的调用也保守计入，不把未知用量当成0。token/费用保持 null。

期限从首次执行开始固定，恢复不重置，包含中断等待时间。实际模型请求超时取原固定超时与剩余期限中的较小值，并保存导出的实际 RuntimeSnapshot 供逐调用查询。HTTP 超时主要约束传输阶段，不承诺网络调用能在期限点立即取消；返回时再次检查期限，迟到结果不发布。已核验批次和已完整保存结果可以无新增模型调用地恢复。

预算用尽、期限到达、原材料变化或原执行 artifact 不可用时停止，并保留稳定错误码及原因。请求重试保留原预算；调整预算/片段需重新预览确认，创建独立请求。运行中不会读取新的默认模型来替代原配置。

预览和确认输入复用 PostgreSQL `research_coverage_artifacts` 不可变产物表，不新增业务表。任务、逐批检查点、调用预算与调用记录沿用 SQLite 检查点系统（`reread_budgets`、`reread_calls`）。补读新分析沿用既有分析历史存储。两类存储不共用分布式事务：输入先保存，任务后入队；最终分析与成功状态在同一 SQLite 事务提交；中断可复用已核验批次。不会修改生产凭据或把材料自动加入评测集。

## 本机验收

1. 如果尚未启用覆盖报告，按 [覆盖报告启用说明](P2_QUESTION_COVERAGE.md) 创建缺失版本/覆盖表。本步复用该表，不需要新增 PostgreSQL 迁移。重启后端和前端；代码内容更新后须新建计划/执行，旧运行版本不能悄悄套用新代码。
2. 选择两篇有全文的论文，以快读或抽样分析完成本轮执行，生成并人工核对覆盖报告。尽量保留真实未读实验/局限片段，便于观察补读差异。
3. 在“优先补读已有论文”建议下，选择论文、填定位词，点击“定位原文片段”。核对原文、页码、已读/未读；此步骤不应发起模型请求。章节提示仍可能受 PDF 解析影响，必要时对照 PDF。
4. 勾选少量相关 E 编号，确认调用预算和期限，再开始补读。默认预算只是上限，不是必须调用次数；不保证小预算一定完成。观察任务、实际扣减和失败原因。
5. 打开新分析，检查旧结论保留、新结论有原文支持、阅读范围及基线分析关联正确。核对原分析及原覆盖报告仍可查看。没有新增结论也属于可能的研究结果，不能强行补造答案。
6. 显式点击“用新分析重新检查覆盖”，对照原、新报告。模型状态变化由人工核对，不以“已回答”标签验收真实性。返回原报告可查看历史；新分支不再自动补读。
7. 可在隔离测试环境验证模型错误后继续、预算用尽、迟到响应及原文变化。不要为制造失败修改真实原文/生产数据库。
