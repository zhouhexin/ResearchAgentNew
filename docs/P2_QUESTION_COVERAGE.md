# P2 第一步：研究问题覆盖报告与补读建议

后续已接通 [人工确认的问题导向补读](P2_TARGETED_READING.md)，下文保留第一步覆盖报告的设计与验收范围。

本步已实现覆盖检查入口；受控测试与用户真实流程验收分别记录。没有自动执行补读、检索或修改已有分析，不代表整个 P2 完成。

相关后端回归 170 项通过；前端构建、覆盖报告组件、计划流程及评审交互检查通过。真实数据库建表和真实模型/浏览器流程尚待本机验收。

## 功能与边界

根据本轮固定计划/问题、分析版本、所选辅助评审版本和阅读范围，逐项给出“已回答、部分回答、未回答、存在冲突”，附回答、理由、缺口和真实原文。评审缺失或失败明确保留状态，不按 supported 标签或支持率推断问题已充分回答。模型覆盖判断仍需人工核对，不等于科研事实或完整领域覆盖。

模型只能选择当前问题、结论、证据和原文片段编号；实际请求 Schema 包含允许编号枚举，后端检查归属、重复与缺失，再从固定上下文提取完整原句。部分回答/未回答/冲突必须说明缺口；冲突至少引用双方片段。字面校验通过不代表语义关系已经正确，不能代替人工审查。

优先建议补读本轮已有论文，尚未确认的章节位置标为待定位；材料仍不足时可建议后续检索。第一步只展示“待人工确认”建议；当前版本可显式定位、确认并补读已有材料，详见补读文档，不会自动补充。原分析、评审和综述均保留。

首版直接提供选定分析中全部带证据结论及其引用片段的上下文，不读取尚未分析的整篇正文；报告明确显示全量/快读/抽样及片段数量。输入超预算时拒绝，不截断、隐去部分证据或自行降级；没有把缺少原文误写成论文没有研究。

## 本机启用和验收

1. 更新代码，在项目目录显式执行：

   ```bash
   python -m storage.init_runtime_versions
   ```

   本步新增 PostgreSQL `research_coverage_artifacts`，保存不可变输入与结果，沿用已有任务系统与版本表。命令只创建缺失表，不迁移或删除旧数据；本次开发未在真实数据库执行建表。

2. 保持 `RESEARCH_RUNTIME_PINNING=true`，重启后端，创建一个**新研究计划/本轮执行**。新根任务会在原角色清单中加入 coverage 的实际 Prompt、Schema、协议、模型和输入/输出预算。原计划没有 coverage 清单时明确拒绝，不在任务中途套用当前默认值。

   可配置默认预算：

   ```env
   COVERAGE_MAX_INPUT_CHARS=60000
   COVERAGE_MAX_OUTPUT_TOKENS=6000
   ```

   修改只影响新根任务；模型超时和 SDK 重试沿用根任务模型配置，模型调用无额外不受控重试。

3. 从文献库或检索路径完成本轮论文分析。在执行结果下方出现“研究问题覆盖检查”；辅助评审可以缺失或失败，不据此伪造语义标签。初始问题来自固定计划，可编辑为1–6项，再显式点击“生成覆盖报告与补读建议”。不会在打开页面时自动发起模型请求。
4. 检查每个问题的状态、依据、缺口和原文。点击引用可查看原文/PDF 对应页；确认模型没有混淆问题、论文或实验口径。建议标明待人工确认，且未自动补读或检索。
5. 可导出独立的 Markdown/JSON 覆盖报告，包含问题、判断、原文引句、阅读范围和版本来源。该报告不会覆盖已有综述，也不会自动更正评审器标签。
6. 超时/失败后选择“按原输入重试覆盖检查”，恢复原输入和配置，不重跑论文分析。若结果已保存但任务中断，继续时恢复结果，无需再次调用模型。完整输入、失败任务和历史结果均保留。
7. 输入分析/原文/评审检查点变化后，旧报告仍可查看和导出，并标为历史；不能用旧结果冒充当前材料。新问题产生独立请求，正常默认配置切换不会更换原执行的 coverage 模型。

## 接口与持久化

```text
POST /api/v1/agent/plans/{plan_id}/executions/{execution_id}/coverage
  {"research_questions": ["方法在什么条件下适用？"]}
  # 可选 review_ids；默认选择本轮已关联的评审，未关联则标为未评审。

POST 同一入口
  {"resume_request_id": "coverage_request_..."}

GET /api/v1/agent/plans/{plan_id}/executions/{execution_id}/coverage
GET /api/v1/coverage/{result_id}
GET /api/v1/coverage/{result_id}/files/md
GET /api/v1/coverage/{result_id}/files/json
```

输入含固定计划、分析与评审指纹、实际提供给模型的材料及运行版本。任务关联原交互、根任务、执行父任务和分析编号；结果保存来源任务、版本、阅读范围和原文位置。表中内容只追加并校验哈希。PostgreSQL 先保存产物，SQLite 再发布状态；跨存储失败可能留下无引用输入，恢复不会重写成功历史。

这属于正常科研业务处理，不授予评测使用权限，不自动加入评测集。未知 token/费用保持 null，人工裁定状态为未采集。
