# 下一步开发计划：让网页真正操作论文

说明文字更新：2026-10-22。这里写的是后续计划，不是已经完成的功能。

## 1. 为什么页面能打开，却还不能真正分析

目前有两套能各自工作的东西：

- Python 程序：在终端里搜索、保存、解析、分析。
- 浏览器页面：有按钮、列表和报告展示，但主要用示例数据。

还需要加上一个连接部分，让页面能告诉 Python：“分析论文 2”，并接收结果。
这部分通常叫 **HTTP API**。你可以把它理解为“网页和 Python 之间的办事窗口”。

以后点击按钮时，不需要另外打开终端输入同样的命令。

## 2. 建议按什么顺序连接

| 顺序 | 要完成的事情 | 你最终能怎样使用 | 怎样判断做成了 |
| --- | --- | --- | --- |
| 1 | 文献搜索、收藏、查询 | 页面搜到论文，收藏后在文献库找到 | 数据库里真有记录，刷新页面仍能查到，重复收藏不增加重复论文 |
| 2 | 全文上传和证据查看 | 在论文下面上传 PDF，看到片段和页码 | 文件归属正确，文字和页码能与 PDF 对上 |
| 3 | 真正的任务记录和执行 | 离开当前页后，分析还继续；回来能看进度 | 任务保存在服务端，重开页面仍能找到；失败原因没有丢失 |
| 4 | 单篇分析 | 点“开始分析”后得到新结果 | 结果来自本次模型分析，五类内容和原文引用检查通过 |
| 5 | 多篇比较和综述 | 选择不同论文，生成并下载报告 | 确实用了至少两篇，引用能查到，三类文件可以下载 |
| 6 | Agent 网页问答 | 在页面提问，查看工具过程和来源 | 回答来自真实请求，问题、结果和引用对应正确 |
| 7 | 统计、历史、整体检查 | 看真实论文数量，查看之前的工作 | 从搜索到导出能在浏览器完整完成一次 |

第 3 项要支持 PDF 解析、论文分析、综述等耗时工作，可以在第 2 项开始时先搭好最小版本。

## 3. “任务记录”到底需要保存什么

例如你点击“分析论文 2”，后台给它一个任务编号。

| 内容 | 举例 |
| --- | --- |
| 做什么 | 分析论文 |
| 给谁做 | 论文 2 |
| 现在怎样 | 排队、进行中、完成、失败 |
| 做到哪一步 | 正在读取全文、等待模型、检查引用 |
| 结果在哪里 | 分析结果的编号 |
| 失败原因 | 模型超时、引用对不上、全文不存在 |
| 什么时候开始和结束 | 创建时间、更新时间 |

网页会每隔几秒查询一次任务状态，这叫“轮询”。
但网页能查询，不代表后台会执行。必须先有真正执行工作、保存状态的 Python 程序。

任务不能只放在一个临时变量里。否则服务重启后，网页就不知道先前的任务去哪了。

## 4. 为什么要单独记录每次分析和综述

现在单篇分析主要写到这样的文件：

```text
paper_analysis_2_2.json
```

再次分析同一篇论文、同一份文档，可能会覆盖同名文件。
这适合学习和简单使用，但不方便回答“昨天的结果是什么”“这份综述引用的是哪次分析”。

后续应给每次运行一个独立编号，并记录：

| 记录 | 要回答的问题 |
| --- | --- |
| 分析记录 | 分析了哪篇论文？读了哪些片段？用哪个模型？什么时候生成？结果在哪？ |
| 综述记录 | 用了哪几份分析？主题是什么？报告在哪里？ |
| 文件记录 | 哪个 PDF 属于哪份文档？浏览器可以怎样安全读取？ |
| 聊天记录 | 这段对话属于哪个会话？助手调用了哪些工具？ |

其中“固定输入版本”是指：综述开始时就记清楚使用哪几份分析。
不能任务刚开始用昨天的分析，运行途中又悄悄换成今天新生成的一份。

## 5. 连接时需要遵守的规则

### 复用现有 Python 功能

搜索、保存、解析和分析已经有代码，网页连接层应调用这些功能。
不要为网页再写一套与终端行为不同的分析程序。

现有终端脚本中有 `input()`，会等待人输入文字。
网页提交请求时，应直接把主题或论文编号传给业务函数，而不是在后台启动终端脚本等待输入。

### 统一论文、全文和证据编号

页面传的是数据库论文编号，比如 `2`，不能把 DOI 或 OpenAlex 编号混在一起。
收到 `P2:E21` 时，需要确认 E21 真的是论文 2 的原文。

### 让页面知道真实的保存结果

收藏时明确返回新增、已有和失败数量。
如果某批数据已经撤销保存，就不能向页面报成功。

### 按报告编号下载文件

用户点击“下载综述”，后端应按报告编号找到对应文件。
不能让浏览器提交任意本地路径，然后直接读取该路径。

### 密钥留在 Python 这边

模型密钥和数据库密码保存在服务端配置中。
设置页面可以显示“已配置”“未连接”，不需要把真实密码或密钥交给浏览器。

## 6. 给继续开发的人看的位置说明

建议新增 `api/` 或 `backend/` 目录处理网页请求，继续复用：

```text
网页按钮
  → 新增的网页接口
  → 搜索、保存、分析等业务函数
  → 现有 tools / storage / agent / review
  → 数据库、PDF、外部检索服务和模型
```

建议新增的记录名称可以是 `task`、`analysis_run`、`review_run`、`document_file`、`chat_session`。
这些是计划中的名字；当前数据库代码只有论文、全文、片段三张核心表。

请求地址和字段约定见 [接口说明](../web/API_CONTRACT.md)，页面与函数对应见 [功能对照](FEATURE_MAP.md)。
