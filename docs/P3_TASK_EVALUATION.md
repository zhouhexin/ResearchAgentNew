# P3 第一步：任务级固定材料集与离线逐例比较

本步在 P0 的版本记录与 P2 的业务验收基础上建立离线评测契约。P2 的真实流程与语义验收仍待分别确认；本步开发不宣告这些验收已完成，也不执行真实回放、联网检索、模型调用、生产写入或版本晋级。

## 交付内容

新增 `evaluation/task_quality.py` 与 `run_task_evaluation.py`：验证冻结的问题/范围/文本材料和人工要求版本，核验记录结果的输入指纹及原文引用，按任务逐例列出运行、来源、人工回答程度和用量；两个运行结果可以成对比较。离线 JSON 文件是评测交换及报告产物，不新增长期业务数据库或生产接口。

示例位于 `evaluation/examples/task_quality_v1/`，全部是开发合成材料，涉及机器人视觉、检索代理两个示意主题；没有导入真实论文或 P33 标签。示例标签由 fixture 作者提供，只验证程序行为，不代表人工独立质量结果。baseline/candidate 均标为 `controlled_fixture`，运行快照编号明确为示例，不能当真实模型联调或版本改进。

## 直接试用

在项目目录运行：

```bash
python run_task_evaluation.py \
  --dataset evaluation/examples/task_quality_v1/dataset.json --check-only

python run_task_evaluation.py \
  --dataset evaluation/examples/task_quality_v1/dataset.json \
  --baseline evaluation/examples/task_quality_v1/baseline.json \
  --run evaluation/examples/task_quality_v1/candidate.json \
  --output-dir outputs/evaluations/task_quality/demo_comparison_001
```

第一条仅检查契约；第二条导出 `report.json` 和 `report.md`。输出目录必须全新，重用目录会拒绝，不覆盖历史。也可只传 `--run` 检查单份结果，不指定输出目录仅打印统计。失败有稳定 `TASK_EVALUATION_INVALID` 编码，返回码1。命令不加载 `.env`，不会访问现有论文库或调用模型。

示例包含两个开发案例、每例两次记录位置，共4个任务分母。基线2个成功、1个失败、1个缺失；候选3个成功、1个缺失，但其中1个成功任务的引句不符合原文。报告应同时呈现运行可靠性变化和来源问题，`promotion_decision=not_evaluated`，不会说候选整体更好。

## 契约与判定边界

- Dataset：有 ID、修订号、人工要求版本。每题保存问题、范围、主题、任务类型、样本自然/合成属性、分组、集合、评测授权声明、材料 ID/论文标识/文档哈希/页码/文本和文本指纹、人工撰写的回答要求及理由。`text_sha256` 是程序规范化 JSON 字符串的 SHA256（复用 `agent.runtime_snapshot.fingerprint`），不是直接对 UTF-8 文本字节散列；`document_sha256` 是提供方声明的原文档哈希，本工具不读取 PDF 验证它。
- 同一 group、paper_key、文档哈希或文本哈希不得跨 development/regression/holdout。调用方应把同主题、同源或变体设为同组；当前只能发现明确身份/哈希重复，不能自动识别改写文本或语义相似论文。示例不是具有代表性的真实问题集。
- Run：固定 Dataset 全量内容指纹、集合、重复次数、frozen/live_search 模式，以及声明的代码、运行快照、Prompt/Schema、工具配置标识。每个 `(case_id,repetition)` 至多一份结果，必须匹配问题/范围/材料的实际输入指纹。未知案例、重复、越界、要求编号错误或版本变化拒绝。没有结果的位置生成 missing 行，不丢弃。
- 本工具检查输入自洽性，**尚未连运行注册表核实实际执行版本/调用，也没有自动回放器**。结果文件的代码与配置标识为提供方声明。`recorded_run` 不因为字段写了这个值就成为独立验证的真实运行。frozen 只表示输入快照固定，不承诺模型逐字复现。实时检索需要另存实际语料及索引时间；本步不评估检索召回或完整领域覆盖。
- 来源核验由程序逐引句检查材料归属、字符范围和精确连续子串。没有带证据发现时为 not_checked；不是通过。范围位置是当前材料文本内部字符偏移。字面通过不代表结论受语义支持，也不推断回答充分。引用失败与任务成功状态分别显示。
- 人工回答程度按每项要求记录 met/partial/unmet/uncertain、复核人、理由、independent 或 after_model_inspection 背景及可选改标前标签。机器标签字段不接受为人工标准。身份和独立性由填写人声明，程序不认证。查看模型后改标须保存旧文件、写前值、更新版本并另建比较，不覆盖原记录。评测集、要求或标注版本改变后旧 Run 指纹不再匹配，需要明确建立对应版本，不能冒充相同条件。
- 运行成功分母为所选案例×预设重复次数。失败、中断、缺失单列，源校验未执行单列；人工未判定不算正确，失败任务的人工判定另列 `non_success_human`。独立人工与受模型影响后判定分开计数，不合成一个“准确率”。没有给出人工标准回答时，不算模型标签准确率。
- token/费用/调用次数/耗时未知为 null，仅汇总已知值并显示已知数量与全部数量，不把未知当真实0。人工回答程度、来源真实性、运行可靠性与成本没有合成总分。
- 自然与合成案例分开统计。对比仅允许相同 Dataset、集合、重复次数、检索模式与运行种类，输出全部配对及变更字段，不自动丢弃失败样本。不同配置可比较，差异须由人员解释。

## 授权、留出与后续

既有论文不会自动进入该集。真实材料需获准评测，记录授权依据、授权人及时间，固定可复核材料，制定人工要求。撤回后应更新当前清单 `allowed=false`，评分拒绝；旧包可能仍可离线打开，因此还需外部权限/删除管理，本工具不承诺全局撤回控制。业务验收声明不等于评测授权。

留出结果必须显式 `--allow-holdout`，仅用于离线验收。程序本身会读取传入 Dataset 来做完整性/分组检查（包括其中的留出要求），不应把含留出要求的文件提供给模型、候选策略或 Evolution。首版没有候选执行器；后续必须另行隔离运行输入与人工答案，不能仅靠命令行开关充当安全边界。

下一小步在明确材料与授权后，建立真实代表性任务及人工基准，再把结果导入与实际执行注册表绑定，接固定版本回放。需要把原始独立材料与模型影响后的复核材料分别保存，不直接复用已参与调优的材料冒充留出验证。
