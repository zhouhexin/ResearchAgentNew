## 1. 从页面找对应功能

| 页面 | 你在页面做什么 | 真正执行时，Python 要做什么 | 现有代码在哪里 | 现在还差什么 |
| --- | --- | --- | --- | --- |
| 工作台 | 看有多少篇论文、多少份分析 | 从数据库和结果记录中统计数量 | `storage/repository.py` 已能统计论文 | 补其他统计，并把数字交给页面 |
| 工作台 | 看最近保存的论文 | 只查询最近的几条论文记录 | `storage/repository.py` | 补“最近保存”和分页查询，连接页面 |
| 文献检索 | 输入主题搜论文 | 请求 OpenAlex 或 Google Scholar | `tools/academic_search.py` | 接收网页搜索条件，返回结果和分页信息 |
| 文献检索 | 打开摘要 | 展示搜索时取得的摘要 | 同上 | 在网页返回结果中保留摘要，不需要模型重新写 |
| 文献检索 | 收藏一篇或多篇 | 检查论文身份、去重并写数据库 | `storage/repository.py`；终端入口是 `sync_papers.py` | 让网页提交所选论文，并返回新增、已有、失败数量 |
| 我的文献库 | 搜标题、按状态筛选、翻页 | 查询数据库，并判断是否有全文、是否有分析 | `storage/repository.py`、`storage/db_models.py` | 补按条件分页查询；不能只把所有论文一次读到网页 |
| 论文详情 | 看基本资料 | 按论文编号查询标题、作者、摘要等 | `storage/db_models.py` | 把查询结果交给页面 |
| 论文详情 | 看这篇论文有哪些全文 | 查询该论文下面的 PDF 或网页记录 | 同上的 `PaperDocumentRecord` | 补全文列表查询 |

| 论文详情 | 提交公开网页全文地址 | 读取网页文字，分段并保存 | `parse_webpage()`、`read_webpage()` 和全文保存程序 | 把这些步骤连起来，并检查地址是否安全 |
| 论文详情 | 预览 PDF、翻到某页 | 给浏览器提供正确的 PDF 文件 | 原文件在 `data/pdfs/`；页面用 `PdfViewer.vue` | 建立文档和文件的对应关系，不能任意读取服务器文件 |
| 论文详情 | 看原文片段列表 | 按文档查询片段和真实页码 | `DocumentChunkRecord` | 补片段分页查询 |
| 任何引用位置 | 点 E21 或 P2:E21 | 找到片段，并确认它属于哪篇论文 | `get_evidence()`、Agent 的 `read_evidence` | 统一按 E 编号查询，返回论文、文档、页码和原文 |
| 科研 Agent | 输入问题、查看回答 | 调用助手、执行搜索工具、整理回答、检查引用 | `agent/workflow.py`、`research_tools.py`、`citation_guard.py` | 补网页问答入口，以及会话和工具执行记录 |
| 论文分析 | 选择已有全文的论文 | 列出哪些论文确实有可读原文 | 论文和文档表 | 补查询，不能把“已收藏”当成“已有全文” |

| 论文分析 | 看旧分析、下载结果 | 查找这篇论文之前的分析文件 | 目前由 `run_paper_analysis.py` 写到 `outputs/` | 增加历史记录；目前同名文件会覆盖，不是完整历史 |

| 文献综述 | 看比较矩阵 | 按问题、方法、实验等整理各篇发现 | `review/matrix.py` | 把数据交给网页；表格方向需转换，见下面说明 |
| 文献综述 | 点生成综述 | 调用模型，检查各条引用和输入论文版本 | `review/synthesis.py`、`db_guard.py` | 补综述任务、进度查询和结果保存 |
| 文献综述 | 下载 CSV、JSON、Markdown | 把已有比较表和报告交给浏览器下载 | `run_literature_review.py` 和 `review/` | 补按报告编号下载的入口 |
| 任务中心 | 看进度、失败原因、结果 | 长期保存任务状态并执行工作 | 目前没有真正的后台任务系统 | 需要新增；网页里的演示进度不是 Python 实际进度 |

| 设置 | 改每页条数、页面配色 | 浏览器自己保存偏好 | `web/src/views/SettingsView.vue` | 这部分不需要调用 Python |

## 2. 以“点击分析论文”为例

以后真正接上时，应该发生这些事：

```text
你在页面选择论文 2，点击“开始分析”
   ↓
页面把“论文编号 2、想读几个片段”交给 Python
   ↓
Python 记下这项工作，先返回一个任务编号
   ↓
页面每隔几秒问一次：这个任务进行到哪了？
   ↓
Python 读取原文、调用模型、检查引用
   ↓
成功后保存分析，页面按编号取回结果
   ↓
你看到五类分析，并能点引用查看原文
```

当前演示模式只是在页面上展示这个过程和已有样本，没有在背后执行新的模型分析。

## 3. 演示模式和真实功能怎样区别

| 功能 | 现在页面里的演示 | 将来接上 Python 后 |
| --- | --- | --- |
| 搜索 | 在已有样本中查找 | 真正到学术来源搜索 |
| 收藏 | 存在当前浏览器里 | 存进 PostgreSQL 数据库 |
| PDF | 可以选本地文件预览；解析会提示需后端 | 上传后生成真实全文和片段 |
| Agent | 提示未连接模型，保留你的问题 | 真正请求模型、执行工具、返回回答 |
| 单篇分析 | 显示已有分析样本 | 对选定论文运行新的分析 |
| 综述 | 显示已有成功报告，主题受样本范围限制 | 对当前所选分析生成新报告 |
| 任务进度 | 页面模拟进度 | 反映 Python 实际工作状态 |
| 引用核验 | 样本缺部分定位信息，显示待核验 | 按数据库的论文归属、原文和位置检查 |

所以，如果终端刚导入论文，网页没有变化，并不一定是保存失败：网页读的还是另一份演示样本。

## 4. 连接时容易接错的地方

### E 编号不能当作“第几个片段”

`E21` 是片段表中编号为 21 的记录。
`chunk_index=21` 则是某一份文档内部的第 22 个片段。它们不是同一个编号。

同样，看到 `P2:E21` 时，需要查清 E21 是否真的属于论文 2。前端已经做了返回结果的归属检查，后端也要检查。

### 收藏不能只返回“成功”两个字

用户需要知道哪些新增、哪些已经存在、哪些失败。
而现有批量保存程序遇到冲突时，会撤销整批修改。
因此，后续连接页面时要明确：整批失败，还是允许逐条成功；不能数据已撤销，却还显示“新增成功”。

### 比较表只是摆放方向不同

Python 导出的 CSV 以“每篇论文一行”保存。
页面上的比较矩阵以“每个研究维度一行”展示。
连接时要把相同内容换个方向摆放，不是重新生成一套结论。

### 正文没变，也要检查旧引用还能不能用

程序给全文计算了一串校验值，字段叫 `content_sha256`，可以帮助发现文字是否变过。
但如果重新切分片段，文字可能没变，E 编号却会变化。因此还需要检查具体片段，不能只看正文校验值。
