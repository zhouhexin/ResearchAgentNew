# P2 执行验收记录

本步补齐业务验收入口，依赖已有任务、固定材料、运行版本、覆盖和报告保存机制。不启动 P3 评测或自动科研，不调用模型、搜索或下载，不更改人工标签和分析。

在执行结果中显式加载可验收产物和历史，选择覆盖报告与综述，检查当前材料与关联。程序核验分析原文、已关联评审、产物所属执行及有效性，并独立检查当前代码/凭据能否恢复原运行配置。未选产物保持未验证，缺失评审单列，不能据“已关联”证明语义正确。代码升级导致旧运行不可恢复，不等于旧科研结论错误。

人工检查独立填写四项：原文引句与来源、结论及覆盖判断、PDF页码跳转、文件实际下载与内容。默认全部未检查；通过或失败必须写明依据。可保存失败及未完成声明，不隐藏问题，不自动计算整体通过或宣布阶段完成。复核人仅为用户自述，未认证身份。程序未验证文件确已保存到用户电脑或浏览器实际交互，须人工核对。

保存前重新检查并比较指纹，拒绝过期声明。记录用已有 PostgreSQL 不可变产物表追加保存，包含所选产物 ID/指纹、文档哈希和阅读范围、固定角色版本、程序检查和人工声明。不新增 PostgreSQL 表，不更改历史产物。业务验收不授予论文进入评测/优化集的权限。

历史记录仍可读取/导出 Markdown、JSON，当前材料或检查状态变化时提示复验，保留保存时检查和人工原话。它是局部执行验收记录，不代表整个领域覆盖、真实模型稳定性或研究系统整体能力。当前版本不聚合全部父分支的失败/预算，不替代任务溯源页或全流程验收文档。服务/数据库不可用时明确报错，不伪装检查通过。

## 本机验收

1. 重启服务；若旧执行运行代码已变化，使用新计划验证当前配置。先完成已有材料分析和独立覆盖/综述，原文和语义人工核对另做。
2. 执行结果底部点击“加载可验收产物及历史”，明确选择覆盖与综述，点击“检查当前材料与关联”。打开页面或检查均不得请求模型。
3. 核对分析/文档版本和阅读范围；未选项保持未验证，没有评审的分析单列。人工对照原PDF、模型理由、实际下载文件及引用跳页，填写四项判断和依据。
4. 保存后刷新可找回声明，导出 Markdown/JSON。未检查或失败允许保存，但不显示“阶段通过”。
5. 在隔离测试环境验证原文变化后拒绝旧指纹保存，历史声明保留且提示复验；不要为制造失败修改真实材料。
