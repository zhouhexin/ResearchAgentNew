记得。我们开发 ResearchPilot 的核心目标是：

> 构建一个基于大语言模型的 AI 科研助手（Research Agent），能够自主检索、阅读、理解和比较学术论文，辅助研究人员发现研究问题、梳理相关工作，并生成有真实文献证据支持的研究报告。

它不只是一个论文搜索工具，也不只是一个能够回答问题的聊天机器人，而是希望成为一个能够完成完整科研文献研究流程的智能体系统。

## 一、ResearchPilot 的核心目标

我们希望它具备六项主要能力：

1. 自主文献检索：根据研究问题，调用 OpenAlex、Google Scholar 等工具寻找相关论文。
2. 论文全文阅读：通过 Jina Reader、PyMuPDF 获取和解析论文，理解摘要、方法、实验与结论。
3. 科研知识管理：使用 PostgreSQL 保存论文、全文、分析结果及其关联关系，并实现去重。
4. 智能论文分析：提取研究问题、研究方法、主要贡献、实验结果和研究局限。
5. 多论文比较与综述：比较不同论文的技术路线、实验表现与局限，形成有证据支持的文献综述。
6. 科研 Agent 自主决策：使用 LangGraph，让模型根据用户问题选择工具、规划检索和分析步骤，并生成研究报告。

## 二、我们特别重视的设计原则

整个项目有三个重要特点：

第一，Agent 能够使用工具完成科研任务。

不是把所有论文塞进 Prompt 里让模型直接回答，而是通过 Tool Calling 让 Agent 调用真实的搜索、数据库和分析工具。

第二，所有重要科研结论都应该能够追溯到论文原文。

例如：

`科研结论 → [P12:E135] → 论文 12 → 原文片段 135 → PDF 页码`

这就是我们从第四课开始一直构建的证据溯源机制。

第三，尽量减少大模型幻觉。

我们通过 Pydantic 结构化输出、原文引用校验、论文身份验证和跨论文证据检查，避免模型编造论文、实验数据、研究贡献或者参考文献。

## 四、我认为项目最终应该达到的效果

假设用户输入：

> 我想研究大语言模型在医学领域的应用。请帮我整理近几年的相关研究，分析主流技术方案，比较研究局限，并找出值得进一步探索的问题。

ResearchPilot 最终应该能够完成：

1

理解研究目标

解析主题、研究范围和筛选条件

2

规划并执行文献检索

检索论文，筛选相关研究并进行去重

3

阅读与分析论文

获取全文，提取方法、贡献、实验和局限性

4

比较多篇论文

梳理技术路线、相同点与差异

5

提出候选研究方向

基于现有证据提出待进一步验证的研究假设

6

生成可核验的科研报告

提供文献综述、比较矩阵和原文证据引用

需要强调：系统提出的候选研究方向应该明确标记为有待验证的假设，不能仅凭有限的论文样本就断言某个方向属于真正的学术空白。

### 还有一个更长远的目标

目前我们的前七课主要解决了：

检索论文 → 理解论文 → 比较论文 → 生成综述

但从项目定位来看，我认为未来最有价值的升级方向是：

让 ResearchPilot 从“文献研究助手”进一步发展为“科研问题探索 Agent”。

也就是不仅总结已有研究，还能够围绕用户的研究目标，迭代检索、发现证据不足之处、提出值得调查的问题，并规划下一步研究。

不过，这属于后续版本的目标，不应该与已经实现的能力混为一谈。

一句话总结：ResearchPilot 的最终目标是成为一个以真实论文为知识基础、以 Agent 为执行核心、以证据溯源为可靠性保障的 AI 科研助手。

## 当前分阶段交付：先理解目标并制定计划

本轮实现“输入研究目标 → 理解范围和条件 → 制定执行计划 → 查看、修改并保存草稿”。
LangGraph 负责模型规划与约束检查，复用当前 Codex/API 配置。明确要求与系统建议分开显示，步骤具有动作类型和前序依赖。
计划草拟成功不等于研究任务完成。用户确认已保存计划后，现可单独启动其中的 arXiv 检索与初步筛选：
使用计划检索词、年份和条件，合并重复文献，由当前模型依据标题和摘要逐项初筛，提供候选清单与可核对的初筛理由。
检索和初筛检查点按计划版本保存，失败可继续；历史结果保留，候选可手动收藏进文献库。
当前已接通检索与初筛，以及人工确认2–5篇候选后的全文获取、解析和全量单篇分析；本轮分析完成后可确认研究问题和比较维度，继续计划内比较、综述和导出。


当前检索范围已扩展 CVPR、ICCV、AAAI、IJCAI，并在“顶刊顶会检索”同一页面提供多选范围：OpenAlex 发现候选，CVF/AAAI OJS/IJCAI 官方论文集核实年度、论文身份及类别；Survey、Demo、Special Track 等不作为主会。
手动检索与计划初筛共用服务；结果可收藏、查询发表记录并继续原有全文分析流程。
官方未确认时保留待核验；CCF 分级本轮尚未导入；其他会议与其他聚合检索来源仍是后续扩展。


检索目录现扩展至13个场所：新增 ACL、EMNLP、SIGIR、NeurIPS、Artificial Intelligence、TOIS、ECCV、ICML、ICLR。
会议主会、Findings/Workshop/其他 Track 与期刊发表分开核验。目录多选、计划检索与初筛、翻译、收藏、全文来源回退共用已有流程。
新增适配以受控协议和交互测试验证；真实网络、来源映射、年度覆盖和官方访问限制仍需在本机验收，不能将代码测试等同于全面联网可用。


## 计划执行小闭环

已接通“已保存计划版本 → 已完成检索与初筛 → 人工确认2–5篇候选 → 收藏 → 全文获取与解析 → 全量分析与证据核验”。
每轮固定计划、检索记录和候选元数据快照，记录计划步骤编号、论文ID、子任务ID、全文ID/内容哈希和分析ID。计划修改后，旧执行保留原快照；新执行必须使用当前版本的检索记录。
有效已有全文/当前完整分析可复用；样本和过期分析不视为全量完成。一篇失败不阻止其余论文；继续时复核原文并沿用分析接口当前配置下的批次检查点。服务重启会标记中断，已保存结果不清空。
本轮完成仅表示所选论文全文与分析完成，不表示比较、综述或整个研究目标完成。真实网络和模型耗时仍需用户本机验收。


单篇分析和计划选文执行现提供可选“快速阅读”，默认最多18个原始片段，优先覆盖已识别的正文关键章节，保留实际页码/章节/片段覆盖说明。
模式独立保存与恢复，结果明确为部分阅读；未识别章节须提示人工核对。全文严格证据核验继续保留，快速结果不作为全量已读。


## 计划内完整流程

现已接通：计划 → 文献检索与初筛 → 人工选文 → 全文与分析 → 研究问题/维度确认 → 比较 → 有证据的综述 → 导出。
报告固定关联执行记录和计划版本，重试仅处理报告阶段；快速阅读范围进入报告和导出。前端分别显示全文分析和报告阶段，完成单篇分析不代表综述已完成，报告可导出也不代表浏览器已保存文件。
