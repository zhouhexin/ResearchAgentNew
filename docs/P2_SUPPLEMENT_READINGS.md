# P2 第四步：补充阅读接回原研究问题

本步依赖执行溯源、固定版本的覆盖检查、受限补检索及既有论文分析。接通“候选手动收藏 → 手动下载/分析 → 选择有效分析版本 → 确认加入原执行的新分支 → 再检查覆盖 → 比较/综述”。不扩大自动化调用范围，不自动下载或分析，不宣告整个 P2 或自主研究验收完成。

## 实现范围

在成功补检索下提供“关联已完成的补充阅读 / 刷新版本”。仅显式点击才查询匹配的已有分析，不调用模型。候选和库中论文须有一致的规范化标题，且 arXiv 编号或明确正式 DOI 相符；没有依据不作模糊匹配。arXiv 编号匹配不承诺 PDF 与候选为同一预印本版本，实际采用的文档 ID、哈希和分析版本单独核验、固定。

用户选1–3篇实际有有效分析的候选，说明纳入理由；原论文全部保留，总数不超过5篇。原执行已满时拒绝，不自动移除或替换材料。重复候选、重复分析、重复论文、无效/外来分析和失效材料均拒绝。初筛“排除/待确认”不会被后台改成“纳入”；用户确认和理由另存，初筛不作为事实证明。

确认后只创建保存分析选择的成功执行记录，阶段说明明确为复用既有结果，不伪称又执行了下载、分析或评审。固定原研究问题、原分析及新增分析，建立新分支，原覆盖报告和分析不改写。选择输入和理由复用 PostgreSQL 不可变产物表，不新增 PostgreSQL 迁移；执行与任务沿用 SQLite。记录候选、补检索结果指纹、原问题/执行、分析指纹、各来源任务和实际运行清单。此业务操作不授权评测使用。

“确认新增论文并重新检查覆盖”会发起一次独立覆盖任务，使用原根任务覆盖角色配置，预算独立于之前补检索。新分析保留自己的生成模型、来源任务及版本，不冒称由当前模型生成。新增材料标为未关联评审，原材料已有评审保留其版本关系。页面切换整组执行结果到新分支，可继续生成比较/综述。覆盖失败时重新提交相同选择复用分支并恢复覆盖，不重跑检索和分析，不重置已有阶段预算。纳入理由或分析选择变化会另存新分支。

这是一轮由用户确认的材料扩展，不是自动多轮研究；系统没有项目级总预算，也不会根据模型标签自动认定缺口已解决。数据字面检查、运行成功和语义正确分别验收。

## 本机验收

1. 重启服务，使用含新代码运行快照的新计划；可复用已有有效论文分析。按补检索文档完成一个无额外来源约束的 arXiv 补检索任务。旧版本不可用时不静默升级。
2. 手动收藏一篇相关候选，在文献库完成下载、解析与分析，检查原文证据是否可靠。返回原覆盖报告的补检索区域，点击“关联已完成的补充阅读 / 刷新版本”。无身份匹配/有效分析时应提示先完成阅读，不能指定其他论文冒充。
3. 选定固定分析版本、填写纳入理由，检查剩余名额、初筛排除风险、实际阅读片段数。点击确认后才应发起覆盖请求。
4. 核对新覆盖报告含原论文和新增论文，新增材料未冒用旧评审；原报告和原分析保留。沿用原问题，人工检查覆盖状态变化是否合理；“已回答”不等于事实证明。
5. 从新执行分支继续比较、综述和导出，核对实际分析 ID；在执行历史中仍能返回旧分支。
6. 在隔离环境验证覆盖调用失败后原输入重试、默认模型切换、失效文档、错误身份及最多5篇限制；不要为制造失败修改真实业务数据。

接口为 `GET/POST /api/v1/supplement-search/{request_id}/readings`。GET 仅查询身份匹配的有效分析；POST 输入 `readings: [{candidate_id, analysis_id}]` 和 `reason`，返回派生 `execution_id`、覆盖任务 `task_id` 和不可变 `reading_selection_id`。
