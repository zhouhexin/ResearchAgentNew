# P1 第一步：计划分析后接辅助语义评审

实现状态（2026-11-18）：已接入计划执行，默认不自动评审。相关后端回归 184 项、前端构建及相关组件交互检查通过；用户反馈本步“真实流程验收完成”。本步完成，不代表整个 P1 已完成。

验收依据为用户本机反馈；本次未重新调用真实模型，也未取得新的逐项运行记录。运行流程验收与科研结论的人工语义复核分别记录，不据此增加语义准确率结论。

## 使用与验收

1. 保持 `RESEARCH_RUNTIME_PINNING=true`，数据库使用已准备好的 P0 四张表。本步无需新增数据库表。更新代码并重启后，创建一个**新研究计划**；原任务仍保留原代码版本，不会静默按新代码续跑。
2. 检索初筛后，确认 2–5 篇论文，在“本轮全文与分析”中勾选“分析后自动辅助评审”，再开始执行。该选择会增加逐条模型请求、等待时间及用量；不勾选时沿用原流程。
3. 每篇依次执行全文、分析、评审。页面分别显示分析和评审状态。评审结果可点击进入固定分析及对应评审，查看原文、模型理由和四类判断数量。
4. 评审失败时，已完成分析仍可打开；“继续本轮未完成部分”会复核原材料，跳过已完成分析及有效评审缓存，只请求未完成的评审。任务历史和旧结果保留。改变默认模型不能替换原角色配置。
5. 全部论文的评审运行完成后，本轮可继续比较和综述。报告 JSON 和 Markdown 包含使用的辅助评审编号，便于追踪；不会按模型标签自动删除分析结论或将报告视作事实证明。

验收重点：两篇分析完成后产生两个评审子任务；中断或失败后只补缺项；父子链路与输入 analysis_id 可核对；复用历史分析时仍使用本轮 Review 配置。与已有独立评审入口共用实现和 references-v2 原文核验，不另建评审策略。

“评审运行完成”指所有条目的模型输出和原文引用通过结构/字面核验，允许出现矛盾、证据不足、需人工核对。模型标签和人工裁定分开，不能把运行成功或支持率解释为语义准确率。

## 固定范围与恢复边界

- 本轮记录 `review_after_analysis`，作为执行去重的一部分；不能把原来仅分析的成功任务当作已经完成评审。旧执行默认保持原范围。
- 评审保存输入分析编号、评审编号、任务历史、完成数和四类数量。新建评审为执行的子任务，同时记录分析来源任务；复用的历史评审保留原父任务，以产物来源关联，不改写旧任务。
- 已固定分析失效、缺失或全文变化时，拒绝静默改用最新分析。原凭据、代码和角色清单不可用时保留检查点并报告，需保留原环境或明确新建执行。
- 本步只自动串联**计划执行中的分析与评审**。独立单篇分析仍由用户发起评审；已有文献库 `select_library_papers` 执行入口、覆盖评估和补充研究未在本步实现。
- 评审失败不重跑成功分析；开启自动评审的本轮需补齐评审运行后才能进入计划报告。用户仍可查看分析和独立使用已有报告入口，未设基于语义标签的发布门槛。
