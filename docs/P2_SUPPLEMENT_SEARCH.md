# P2 第三步：人工确认的受限补检索

依赖固定运行配置、覆盖报告和已有材料补读。对 `search_later` 建议，用户填写并确认1–2组检索词、每组1–10条候选、工具与模型调用总预算2–24次，以及10–1800秒期限。先提供 arXiv 路径；原计划限定会议/期刊、正式主会或其他来源时拒绝，不静默扩大范围。查询继承原计划年份、纳入/排除和语言条件，围绕原覆盖问题初筛。

检索与摘要初筛复用现有程序、严格引用核验和去重。候选可手动收藏，再通过文献库选择后续下载、分析；不自动获取全文，不把摘要筛选当作问题已回答。没有生成新综述或修改旧分析/覆盖报告。原始候选最多20条，最多一轮；仅限用户确认的查询范围，不表示完整领域覆盖。已有论文出现在外部结果中时仍可能保留，沿用收藏去重，不虚称都是新论文。

预算复用 SQLite 检查点账本：每次 arXiv 工具调用和初筛模型调用预扣一次，失败也扣减，无自动重试。模型参数沿用原根任务 Search 配置，SDK重试为0，实际超时收紧到剩余期限并另存运行快照。arXiv 节流等待后再次核对期限，HTTP超时取剩余期限和既有阶段超时的较小值；网络请求不能保证立即取消，超期响应不发布。此处调用数是业务工具/模型调用次数，不是底层重定向、TCP连接次数；token与费用保持未知。

同一确认请求恢复不重置预算和期限，已完成查询/初筛批次不重跑。预算不足可能只留下候选或部分初筛，明确显示失败，不当作全部完成。变更检索词或预算创建独立确认请求；每个确认请求一轮，不是整个研究项目的全局预算。已保存完整结果但任务状态写入中断时，直接恢复保存结果，不再次调用。

确认输入和完整结果复用 PostgreSQL 不可变覆盖产物表；运行进度单独保存在 SQLite `supplement_search_checkpoints`，避免把派生问题/查询冒充原计划修订。任务关联原覆盖任务、研究问题、计划版本和运行清单。材料变化或旧代码/凭据不可用时拒绝；历史结果仍可查询。本步不新增 PostgreSQL 迁移、不改变评测授权。

## 本机验收

1. 重启服务并使用新计划（更新代码后旧运行版本不自动升级）。覆盖表未初始化时，先按 P2 覆盖文档启用。使用没有额外发表来源约束的计划，完成已有论文分析、覆盖检查；有真实缺口时优先补读，仍不足时选择后续检索建议。
2. 在建议下填写英文查询，确认预算后点击补检索。仅打开页面不得查询外部服务或模型。
3. 核对候选标题、原始摘要及逐项初筛理由/引句，人工判断相关性；模型初筛不能证明全文结论。手动收藏后到文献库选择后续流程。
4. 观察实际预算扣减和原报告保留。失败后按原请求继续，已完成查询不重复；预算用完/期限已到明确停止。修改预算属于新请求，需重新确认。
5. 在隔离环境验证来源约束、过期材料、预算用尽及恢复。真实模型/数据库/浏览器流程和人工语义复核分别验收。
