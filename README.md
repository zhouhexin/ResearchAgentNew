# ResearchPilot：帮你找论文、读论文、整理综述

你可以用这个项目完成：**搜索论文 → 保存论文资料 → 导入 PDF → 分析论文 → 比较多篇论文 → 导出综述。**

当前浏览器已接通 **arXiv 检索、收藏、论文详情、PDF 上传解析、获取原文、单篇 AI 分析、多篇比较与综述和任务查询**。请在设置中选择“真实 API”。Agent 对话仍需继续接入对应后端接口；终端脚本可以独立使用。

设置页新增“模型连接检测”：可检测普通对话，或用内置样例验证论文分析结构与原文引用。
检测在后端执行，不依赖论文数据库，支持对照当前配置、SDK 和 requests 传输；不会修改服务端配置。
结果保存在任务中心，刷新页面后可以恢复。连接失败时展开“查看连接诊断”，可查看 TCP/TLS 阶段、连接节点及异常链。
检测通过只表示这次短请求或样例通过，真实论文的各批次仍独立校验。

论文检索已改用 arXiv，检索页面不再提供 OpenAlex。已有文献记录保留。新 arXiv 记录使用稳定的 arXiv DOI 收藏，获取原文优先直接访问 arXiv。

## 2. 几个脚本怎样区分

| 你要做的事 | 运行哪个文件 | 得到什么 |
| --- | --- | --- |
| 搜普通网页，并读取网页内容 | `main.py` | 搜索结果文件和网页文字 |
| 搜论文，只想把结果保存成文件 | `academic_demo.py` | `outputs/` 中的论文资料，不写数据库 |
| 搜论文，并加入自己的文献库 | `sync_papers.py` | 数据库 `papers` 表中的论文基本资料 |
| 把一篇论文的 PDF 加进系统 | `document_demo.py` | 全文文字、原文片段，以及它们所属的论文 |
| 直接向研究助手提问 | `run_agent.py` | 助手回答和可用的原文引用 |
| 分析一篇已经导入全文的论文 | `run_paper_analysis.py` | 研究问题、方法、贡献、实验结果、局限性 |
| 比较多篇已分析论文，写综述 | `run_literature_review.py` | 比较表、综述和引用 |

**特别注意：搜索到了论文，不代表已经下载了 PDF；导入了 PDF，也不代表已经分析过。**

## 3. 在终端中完成一次研究

以下命令在项目主目录运行，也就是能看到 `sync_papers.py` 的目录。

### 第一步：选好 Python 环境

```bash
conda activate py311
```

这是项目一直使用的本地 Python 环境。如果用 PyCharm，请选择这个解释器：

```text
/opt/homebrew/anaconda3/envs/py311/bin/python
```

项目里另有一个 `.venv` 文件夹，它不一定装有同样的软件包。不要只看它也叫 Python，就以为两者完全一样。

需要补装依赖时运行：

```bash
python -m pip install -r requirements.txt
```

“依赖”就是程序运行时需要用到的软件包，清单放在 `requirements.txt`。

### 第二步：检查配置并准备数据库

数据库地址和模型密钥保存在根目录 `.env`。已有这个文件时，继续使用它；新安装项目可参照 [.env.example](.env.example) 填写。

```bash
python -m storage.init_db
```

这条命令会在数据库中创建缺少的表。它不负责安装 PostgreSQL，也不会自动替你配置数据库连接。

### 第三步：搜索论文并加入文献库

```bash
python sync_papers.py
```

输入研究主题，比如“单光子 深度估计”。当前脚本最多搜索 20 篇，年份为 2022—2026。

这一步只保存标题、作者、摘要、DOI 等基本资料。**不会下载 PDF，也不会保存论文全文。**

### 第四步：把正确的 PDF 关联到论文

先准备好 PDF，再运行：

```bash
python document_demo.py "data/pdfs/你的论文.pdf" --paper-id 2
```

把路径换成真实文件路径，把 `2` 换成这篇论文在 `papers` 表中的 `id`。
`--paper-id 2` 的意思是“把这个 PDF 归到第 2 条论文记录下面”。程序不会自动判断你选的 PDF 是否对应这篇论文。

### 第五步：分析这篇论文

```bash
python run_paper_analysis.py 2
```

这里的 `2` 仍是论文编号。现在默认按顺序分批分析全文，每批最多 2 个片段，通过原文核验后就保存。失败后用相同命令继续，已完成部分不会重跑；最后合并成报告。详见[分批分析使用说明](docs/BATCH_ANALYSIS_GUIDE.md)。

成功结果在 `outputs/`，文件名形如：

```text
paper_analysis_2_2.json
```

两个数字分别是“论文编号”和“文档编号”，不一定相同。请以实际生成的文件为准。

### 第六步：比较至少两篇论文

先按相同步骤完成另一篇论文的导入和分析，再把成功的分析文件交给综述程序：

```bash
python run_literature_review.py outputs/paper_analysis_2_2.json outputs/paper_analysis_3_3.json --topic "单光子三维成像中的深度估计与目标姿态获取"
```

文件名是示例，需要替换成你自己的结果。主题也要符合论文内容。
默认在 `outputs/review07/` 生成比较表、JSON 结果和 Markdown 综述。

## 4. 打开浏览器页面

另开一个终端：

```bash
cd web
npm install
npm run dev
```

打开终端显示的地址，通常是 `http://127.0.0.1:5173`。

当前默认是**演示模式**：可以查看页面布局、已有分析和综述样本，体验引用查看等操作。
它不会自动显示你刚写入数据库的论文，也不会因为点了按钮就开始真正分析。
原因是页面和 Python 程序之间的连接部分还没做好，详见 [前后端功能对照](docs/FEATURE_MAP.md)。

## 5. 常见问题

### 使用本机 Codex 登录和订阅额度

论文分析、综述生成（页面和 CLI）及模型检测支持通过官方 `codex exec` 复用本机 ChatGPT 登录。
此方式消耗该账号的 Codex 用量，仍受订阅额度和速率限制。参见 [Codex 官方非交互模式说明](https://learn.chatgpt.com/docs/non-interactive-mode)。

先在启动后端的同一系统用户和终端检查 `codex login status`；不是 ChatGPT 登录时，执行 `codex login` 并在浏览器登录。
然后在 `.env` 配置并重启后端：

```dotenv
LLM_PROVIDER=codex
CODEX_CLI_PATH=codex
CODEX_MODEL=
CODEX_USE_SYSTEM_PROXY=true
```

若后端找不到 CLI，可将 `CODEX_CLI_PATH` 设为 `command -v codex` 返回的绝对路径。
`CODEX_MODEL` 可指定该账号可用的模型；留空使用 CLI 内置默认模型。本集成不加载用户 `config.toml`，
避免其中的 API 提供商、MCP 或代理服务配置改变认证与任务行为，但仍保留环境网络代理和现有登录目录。
默认同时通过 Codex 的 `features.respect_system_proxy` 读取操作系统代理；可设 `CODEX_USE_SYSTEM_PROXY=false` 禁用系统代理，
`--no-proxy` 会同时禁用环境代理与系统代理。GPT 模型标识统一为小写，例如 `gpt-6-luna`。
无需复制 `auth.json` 或将登录令牌填入 `.env`；Codex 自己管理登录和刷新。
Codex 模式忽略 `LLM_API_KEY`、`LLM_BASE_URL`、`LLM_MODEL`、Qwen 思考开关和 API 输出 Token 配置，
也不会自动回退到 API Key 计费。`LLM_READ_TIMEOUT` 在此模式表示单次 CLI 调用总时限；超时会回收进程组。
原文经标准输入传入独立临时目录，使用只读沙箱，关闭 shell、搜索及多代理工具；临时结果使用后删除。

验证连接与样例原文引用：

```bash
python run_paper_analysis.py --check-llm --structured --timeout 120
```

也可在页面“设置 → 模型连接检测”选择“当前配置”。成功后正常发起论文分析或综述。
切换 API/Codex 会建立不同的分批计划，旧检查点保留，不混用；原文引用要求不变。
登录失效、额度/速率限制、执行权限、连接失败、调用超时会分别提示。
CLI 失败时从 JSON 失败事件提取安全诊断，区分 DNS、代理、TLS、HTTP 状态及 WebSocket/响应中断；
仅保留阶段、域名、状态码、退出码和代理环境变量名称，不保存异常原文、完整 URL 或令牌。
`run_paper_analysis.py` 将安全诊断打印到终端并保存至 `outputs/codex_diagnostic.json`，页面任务的 `error.diagnostic` 提供同样的详情。
`diagnose_llm.py` 和 `--http-backend sdk/requests` 仅适用于 API 模式。
现有 `run_agent.py` 工具调用 Agent 仍使用兼容 API 配置，不经过此文本分析桥接。
回到原有模型服务时，设置 `LLM_PROVIDER=openai` 并保留原 API 配置后重启。

### API 连接和原文核验

“科研 Agent”页面当前实现研究流程的第一阶段：输入自然语言研究目标，由 LangGraph 调用当前模型理解主题、
研究问题、时间范围、筛选条件、检索词、比较维度和交付物，并草拟有依赖顺序的执行计划。
模型补充的年份和篇数会标为建议；明确年份和原始篇数要求保留用户原话，不静默覆盖超出本轮能力的要求。
页面可修改目标理解、范围、研究问题和各步骤的文字说明，保存版本，并通过任务中心或浏览器刷新恢复。
制定计划本身不会开始研究。确认并保存后，可在下方点击“开始检索与初筛”，由 LangGraph 执行 arXiv 检索、去重和模型摘要初筛。
每个检索词默认取前10条（可改为1–20条，最多8个检索词），按计划的首次提交年份范围检索；这与后续深入分析2–5篇的数量分开。
候选论文分为“建议纳入 / 排除 / 待确认”，逐项展示计划条件、中文解释及标题/摘要中的逐字依据，信息不足时保留待确认。
检索元数据不能代替全文证据；不会自动下载、分析或生成报告，也不代表完整领域查新。
当前支持 arXiv 与 CVPR/ICCV OpenAlex/CVF；其他指定来源会明确阻止执行。CVPR 的使用方式见下节。
检索与初筛逐批保存，刷新或任务中心可恢复。失败后点击“继续未完成检索与初筛”只处理未完成部分；
相同计划版本、模型和检索预算会复用结果。修改并保存计划、切换模型或检索预算会建立独立记录，历史结果保留。
勾选候选论文可“收藏所选论文”，随后到论文库执行已有的全文获取与分析流程；收藏每次最多100篇。
API 输出预算可用 `RESEARCH_PLAN_MAX_OUTPUT_TOKENS` 配置，默认 6000；Codex 使用现有登录和 CLI 输出管理。
切换到真实 API 模式并重启后端后，可用“梳理近五年机器人视觉研究，比较精度和能耗，分析3篇论文并形成带证据的报告”进行验收。

检索初筛验收建议：打开已通过验收的计划，确认检索词含英文专业术语，保存修改；
先将“每个检索词结果数”设为3–5，点击“开始检索与初筛”。检查检索词/年份、去重数量、分类和逐项摘要依据；
刷新页面后结果应保留，重复点击复用结果；修改计划并保存后应生成新版本，旧记录仍可切换查看。
勾选1–2篇并收藏，在论文库确认；如果任务失败，先查看错误，再继续未完成部分，已完成检索词和已核验初筛不会重跑。

页面生成综述时，在选择 2–5 篇有效分析并查看比较矩阵后，系统会自动推荐最多 3 个研究问题。
每个问题展示推荐理由及至少两篇论文的证据引用；你可点选、修改或自行填写，然后点击“生成综述”。
推荐使用当前模型配置（API 或 Codex），与正式综述分别作为后台任务保存；推荐不会直接生成报告或替你选定问题。
相同论文和分析版本的推荐记录及已编辑问题可在同一浏览器恢复，任务中心也提供查看入口。
推荐失败可重试或自行填写；换论文或分析版本会清除旧选择。演示模式不调用模型或伪造推荐。

新生成的综述默认采用详细写法：小标题和主题句后展开解释段落，每段单独保留引用，最后给出围绕研究问题的综合回答。
材料充分时参考篇幅约 2000–3500 个中文字；证据不足时应更短，不要求模型凑字数。
综述材料按论文和研究维度均衡选择，每类最多 8 条已核验发现，并覆盖靠后的分析内容；总输入预算为 60000 字符。
引文保留完整内容，超预算时跳过整条发现并记录材料覆盖情况，不截断引文。此限制不是重新阅读全文。
API 模式的综述输出预算由 `REVIEW_MAX_OUTPUT_TOKENS` 单独控制，默认 10000，不影响单篇分析或问题推荐；Codex 输出长度仍由 CLI 管理。
页面、JSON 和 Markdown 均保留解释段落及其引用；旧报告继续可读，但不会自动扩写，需重新生成综述，无需重做有效的单篇分析。

综述引用显示为 `[1，第6页]`：文献编号对应报告参考文献，页码为 PDF 文件页码。点击引用可查看冻结分析中已核验的完整原文引句，并展开当前片段上下文；同一证据片段关联多个引句时全部列出，不替模型猜测唯一支持句。内部 `P28:E689` 编号仍保留在证据详情和 JSON 中。
引用对应的本地 PDF 可读取时，点击引用会在站内侧栏同时打开 PDF 阅读器并跳到证据记录的页码，旁边保留完整引句。读取的是该证据所属的具体文档，不会替换为同篇论文最新上传的其他文件。可用页码控件翻页；未记录页码时打开首页，原 PDF 缺失或网页来源仍展示文本证据。当前复用浏览器内置 PDF 阅读器的页码跳转能力，尚未标注句子位置。
Markdown 导出使用可跳转脚注，包含论文标题、页码、完整引句和内部定位，不再截取片段前 300 字。请使用支持 Markdown 脚注的阅读器。已有 API 报告重新打开或导出即可使用新格式，无需重新调用模型；历史报告依然使用原报告的快照，不替换为最新分析。

| 遇到的情况 | 先检查什么 |
| --- | --- |
| `papers` 有论文，分析却说没有全文 | 还需要用 `document_demo.py ... --paper-id ...` 导入正确 PDF |
| 数据库里有新论文，页面却没有 | 页面默认使用独立的示例数据，还没连接数据库 |
| 模型一直超时 | 先运行下面的小请求检查，再看网络、代理和模型服务 |
| 引用原文不匹配 | 模型给出的引文在对应片段里找不到，查看 `outputs/` 中的错误对照文件 |
| 综述主题和论文不搭 | 更换主题或输入论文，不要强行拼出引用 |

检查模型能不能回应简单问题：

```bash
python run_paper_analysis.py --check-llm
```

怀疑代理影响连接时，再对比：

```bash
python run_paper_analysis.py --check-llm --no-proxy
```

小请求成功，只能说明简单对话能用，不保证复杂论文分析一定成功。
进一步检查与页面相同的论文分析结构和逐字引用核验（不访问数据库）：

```bash
python run_paper_analysis.py --check-llm --structured --timeout 120
```

Qwen3.8-Flash 默认开启深度思考，复杂结构化请求可能明显慢于普通对话。
信息提取场景可在 `.env` 中设置 `LLM_ENABLE_THINKING=false` 和
`LLM_MAX_OUTPUT_TOKENS=4096`，随后重启后端。思考开关是供应商扩展参数，
其他不支持的模型须留空。输出超过上限时会判定为截断失败，不能作为完整报告。
这些请求参数的调整可复用已核验的批次，不改变原文或分批计划。
函数调用返回的引用项如果仅多包了一层 `evidence`，解析器会无损移除这一层后重新执行字段与原文检查。
缺失字段或有歧义的引用仍会失败；分批重试会向模型提供具体字段错误和正确的引用结构。
引用核验前会恢复空白差异和一层常见 JSON 转义（如字面 `\n`），最终保存对应片段中的精确连续原文。
优先保留模型指定的合法片段编号；在该片段无法匹配时，只有引文能唯一对应本批另一片段，才修正编号。
未知/越界编号、多个候选、改数字或标点、自行合并断词、跨片段拼接仍会失败；不搜索未提供的全文，也不删除失败结论来强行通过。
该修复不改变原文、提示词、Schema 或分批计划，已核验的批次仍可继续复用。
PDF 和网页新解析均优先在段落、句子边界分片。默认窗口上限为 1200 字符，相邻窗口尽量保留不超过 200 字符的完整句子上下文；
单句超长时回退到词或字符边界。PDF 窗口不跨页，所有片段仍是全文中可精确定位的连续子串，原文核验规则不变。
`parse_pdf`、`parse_webpage` 和 `build_document` 可通过 `chunk_overlap=0` 禁用重叠，或指定小于 `chunk_size` 的重叠上限。
网页和命令行发起论文分析前都会检查旧版 `pymupdf` / `pymupdf-native-v1` 全文：有可读取的关联本地 PDF，且按旧规则提取的全文哈希一致时，
会重新解析并保存为 `pymupdf-native-sentence-v2`，再按新片段建立分析计划。旧批次保留，但不混入新计划。
页面遇到已有运行中的分析时会直接复用该任务，不会在这次请求中替换原文。文件与原文不一致时会停止并提示核对文件。
也可以手动重新解析已关联的本地 PDF：

```bash
python document_demo.py --paper-id 23
```

将 `23` 换成对应论文编号。新解析保留 PDF 自身文本顺序，并重新校验所有页码、片段和字符位置。
重新分片可能保持全文哈希不变，但片段边界、编号和批次计划会更新。旧版分析保留为历史结果；重复导入相同新切片时会复用记录。
模型超时的新诊断会区分连接、读取、发送或连接池等待超时；读取超时指等待网络数据的时间，
不保证等于模型实际生成总耗时。
`ConnectError → ConnectionResetError` 表示建立连接时被重置，不能仅凭此判断是服务端、代理还是网络链路断开。
网络或上游服务失败后的重试会等待 2、4、8 秒（由 `ANALYSIS_BATCH_RETRIES` 控制尝试次数，最大额外重试 3 次）；
每次使用新的客户端，已完成批次继续复用。持续断连仍需排查实际后端网络或模型网关。
持续出现建连重置时，在启动后端的同一终端运行 `python diagnose_llm.py`。
该命令用同一配置交替测试 SDK 和 requests 各两次，并单独测试 TLS 直连；共发送最多四个简短对话请求。
报告保存在 `outputs/llm_network_diagnostic.json`，不包含密钥、请求头、响应正文或异常原文。
若两种 HTTP 客户端结果不同，需进一步排查客户端或网络设备的差异处理；若都失败，则继续排查网络或上游服务。
若小请求正常而真实分析持续断连，可用相同的真实分析切换 HTTP 传输进行对照：

```bash
python run_paper_analysis.py 23 --scope sample --max-chunks 18 --batch-size 3 --http-backend requests
```

该选项只更换 HTTP 传输，模型、消息、结构化输出、逐字引用检查和断点计划保持相同；TLS 证书仍会验证。
默认仍使用 SDK 自带传输。确认 requests 在实际环境可用后，可设置 `LLM_HTTP_BACKEND=requests` 并重启后端，使页面也使用它。
诊断错误中的 `network.stage` 会记录 SDK 的 TCP/TLS 阶段，或 requests 的发送/读取阶段，帮助定位断连位置。
连接失败时，检查命令会显示域名解析、代理、TLS 或连接中断等具体原因及底层异常链。
请使用启动后端的同一个 Python 环境和终端运行，以便使用相同的网络与代理配置。
页面新发起的分析和综述也会显示具体原因，并分别保存安全诊断至
`outputs/api_analysis_errors/任务ID.json` 和 `outputs/api_review_errors/任务ID.json`。
之前的失败任务不会自动补出原因；网络恢复后可在原全文任务上继续未完成批次，复用已经保存的进度。
更多参数与错误文件说明见 [项目说明](docs/PROJECT_GUIDE.md)。

### 顶刊顶会检索与发表核验（CVPR、ICCV、AAAI、IJCAI）

重启后端并刷新前端后，在“文献检索”切换“顶刊顶会检索”，勾选 CVPR、ICCV、AAAI、IJCAI 中的一个或多个会议，输入 `monocular depth`，选择2024年，先取1–5条候选。
也可在“科研 Agent”的已保存计划中将“检索范围”改为 CVPR，保存后执行；自然语言目标可写“检索2023–2025年 CVPR 正式主会的单目深度估计论文”。
“仅显示/保留官方核验的主会论文”将过滤未核验候选和 Workshop，不会把索引记录自动当作主会录用。

OpenAlex 负责候选发现；系统读取真实 `/sources` 记录解析 CVPR 来源编号，排除 Workshop 来源，不内置示例 S 编号。
如自动映射无法确认，可在 `.env` 配置 `OPENALEX_CVPR_SOURCE_IDS` 或 `OPENALEX_ICCV_SOURCE_IDS`（逗号分隔、已核实的编号），程序仍会核对名称和 conference 类型。
现有 `OPENALEX_API_KEY` 会用于来源解析及候选检索；本模块不调用 LLM，只有计划中的摘要初筛会调用当前 Codex/API 模型。

CVF 核验使用官方 HTTPS 页面，检查标题、作者、可取得的 DOI，以及年度/主会或 Workshop 路径。
官方来源不可用或身份不一致时保留“索引记录，待核验”；摘要初筛结论与发表身份分开显示。
默认每页5条、最多20条，相关性排序；年份指正式发表年份。总数为 OpenAlex 索引候选总数，主会过滤只作用于本页候选。
不会将取到的一页候选称为完整会议论文清单。缓存成功 HTTP 响应，OpenAlex/年度目录24小时、官方论文页7天；单页核验有等待预算，未核验部分不会冒充已确认。

候选可收藏入现有论文库；浏览器提交的发表核验标签不被信任，后端在收藏时重新核对并保存发表记录。
论文详情展示官方核验链接；已确认记录不会因临时网络故障降级。获取原文时，明确的 CVF 页面会优先从官方 PDF 取全文，失败后再走原有来源。
新增的四张发表目录表会在初始化或首次使用时建立，不删除已有论文。也可以先执行 `python -m storage.init_db` 初始化。
CVPR 的 CCF 目录等级本轮尚未导入，页面明确标为待导入，不把未核实的2026目录信息作为事实显示。

计划默认复用执行快照；需要更新官方核验时，点击“重新检索并核验 CVPR”，创建新运行并保留历史。
直接检索与计划共用同一检索/核验服务。来源响应、查询预算、主会筛选和年份口径均可追溯；摘要不足时仍需进一步获取全文。

可单独运行真实联网检测（读取项目 `.env`，不调用模型、不修改论文库）：

```bash
python diagnose_cvpr.py --query "monocular depth" --start-year 2024 --end-year 2024 --limit 1
```

需要只看官方确认主会时加 `--main-only`。诊断保存为 `outputs/cvpr_search_diagnostic.json`，只保存安全的错误类别和状态码，不保存密钥或异常原文。
`ok=true` 表示候选检索完成；还需检查 `papers[].publication` 或 `publication_counts` 才能确认官方核验是否成功。

arXiv、CVPR 检索结果和摘要详情保留原文，增加“中文翻译”区域。点击“生成中文翻译”后，

相同标题、完整原文、模型/端点、方法及翻译版本复用已保存结果；刷新后自动恢复缓存，不自动发起新的模型调用。
没有摘要或超过24000字符时不调用模型，也不静默截断原文。翻译失败可重试，完整原文仍可阅读。

```bash
python diagnose_cvpr.py --venues aaai ijcai --query "depth estimation" --start-year 2024 --end-year 2025 --limit 2
```

### 扩展目录：NLP、ML、信息检索与两个期刊

同一“顶刊顶会检索”页面和研究计划现支持13个会议/期刊，可混合多选。新增 slug 为
`acl`、`emnlp`、`sigir`、`neurips`、`artificial-intelligence`（AIJ）、`tois`、`eccv`、`icml`、`iclr`。

| 场所 | 正式核验来源 | 类别规则 |
| --- | --- | --- |
| ACL、EMNLP | ACL Anthology 论文页及明确的 DOI | Long/Short/Main 与 Findings、Demo 分开 |
| ICML | PMLR 具体论文页 | 必须确认对应卷为 ICML；不能把整个 PMLR 系列当作 ICML |
| NeurIPS | 正式 proceedings 或 OpenReview 录用记录 | Main Conference 与 Datasets and Benchmarks 等分开 |

### PDF 下载超时与进度

PDF 下载时限独立于模型配置。原下载器固定120秒总时限，现默认每个 PDF 地址600秒，可在 `.env` 配置后重启后端：

```dotenv
PDF_DOWNLOAD_TIMEOUT=600
PDF_READ_TIMEOUT=60
PDF_CONNECT_TIMEOUT=10
```

三项分别表示单地址总下载预算、连续等待响应数据的读取时限、建立连接时限。
页面任务显示下载站点、已接收数据、耗时和平均速度；失败时区分 PDF_DOWNLOAD_TIMEOUT（总预算到期）、PDF_READ_TIMEOUT（等不到数据）、PDF_CONNECT_TIMEOUT（连接超时）。
时限支持正数，最大分别为3600、600、120秒；无效配置在创建任务前返回422。未完成的下载临时文件仍会清理，不把部分文件当作可用PDF保存。
不同来源返回同一地址（包括已尝试的跳转地址）时，本次任务跳过重复请求；同一论文已有活动下载任务时重复点击复用任务。
新任务的诊断记录主机名、阶段、字节数、耗时、时限与错误类别，不记录查询参数、请求头和异常原文；旧任务无法补回当时未记录的传输数据。


下载状态会分别标识“取得候选地址”“收到HTTP响应”“确认PDF文件头”“完整下载并解析”。增加时限不能保证成功；地址返回404、登录/拦截网页、只有文件头后连接停滞，属于不同情况。
只有收到实际 `%PDF-` 字节才标记已确认文件头；HTTP 200 或 Content-Type=application/pdf 本身不能证明拿到了有效PDF。旧任务没有保存这些证据，需新任务重试后才能进一步判断。


### 按计划获取全文与完成单篇分析

重启后端并刷新前端后，在“科研 Agent”中执行已保存计划的检索与初筛，再勾选2–5篇候选。
点击候选列表下方“确认所选论文并执行”，系统会收藏论文、获取并解析全文、逐篇执行全量分析和原文引用核验。
本轮确认篇数可以与计划建议篇数不同，页面会明确显示两者；浏览器只提交候选编号，论文信息取自服务端检索快照。

“本轮全文与分析”显示每篇的全文/分析状态、实际结果链接、错误和活动子任务进度。更换页面不会停止后台任务，刷新可恢复记录。
失败后点击“继续本轮未完成部分”：复用可读全文与当前完整分析，缺失分析沿用原有批次恢复机制；手动上传全文后也可回到本轮继续。
若该论文已有其他页面发起的任务在执行，系统关联该任务并提示待其完成后继续，避免重复提交。
重试采用当前模型配置；原文或模型等分批条件改变时不混用不兼容检查点。

执行记录固定对应计划版本和所选论文；历史执行可以继续原版本，新的选文须使用当前版本完成的检索记录。
计划须包含按顺序的全文获取和单篇分析步骤；还未接通的前置动作不会被静默跳过。
任务中心新增“计划全文与分析”，可返回对应计划和检索记录。

验收建议：确认两篇论文，观察全文与分析结果；模拟一篇请求失败，确认另一篇仍完成；恢复后继续失败篇并刷新页面，检查执行版本、进度和结果链接仍一致。
本阶段不自动执行比较/综述；“本轮完成”不表示整个研究目标完成。


### PDF 断词引文的候选选择修复

对于可在同一证据编号中唯一定位的 PDF 行尾断词、换行或转义差异，分批分析可补充一次结构化候选确认请求。
该请求只允许模型选择候选编号，由后端回填对应的原文连续子串，再执行原有严格核验。模型不能在此阶段重写 quote。
改词、改数字、未知证据编号、跨片段拼接或存在歧义时不会进入该修复；模型拒绝、漏选、重复选择或返回非法编号也不会发布结果。
该修复保留已有原文、模型分析结构和批次指纹，继续时复用已完成批次。真实模型仍需返回有效选择，受控回归通过不等于实际论文批次已完成。


### 快速阅读：正文关键章节优先

“论文分析”的“阅读范围”新增“快速阅读（正文关键章节优先）”；科研 Agent 的“本轮全文与分析”也可选择此模式。
单篇分析默认最多18个片段，可调8–50；计划快速阅读固定18个片段。它按标题位置及片段与章节的实际重合范围，优先分配摘要/引言、方法、实验结果、结论/局限，再补充其他正文；参考文献与附录不主动纳入。
每类已识别的关键章节先覆盖开头，再覆盖末尾并轮流补充中间片段，避免某个长章节独占全部预算。窗口保持原有内容、证据编号、页码和字符偏移，继续执行严格引用核验。

结果和运行中的任务会展示实际阅读片段数、页码、章节覆盖与未识别标题。跨章节窗口可计入多类，章节统计不能简单相加作为总片段数。
若未识别出关键标题，会对可辨认的正文取样，并明确提示人工核对；标题识别不能保证适配所有论文排版。快速阅读即使报告生成成功，也不表示已通读全文。

快速阅读与全量/均匀抽样具有独立检查点。切换模式需要新任务，不能混用旧批次。已有当前全量分析可用于快速模式；快速结果不满足全量执行要求。
已有任务继续按原范围运行，模式不会在中途切换。默认仍为全量分析，需主动选择快速阅读。

CLI 示例：

```bash
python run_paper_analysis.py 33 --scope fast --max-chunks 18 --batch-size 2
```

本地选片检查中，论文33从141个片段、71批缩减至18个片段、约9批；这是覆盖范围与调用数量的变化，不是已测得的端到端模型耗时承诺。


### 计划内的比较、综述与导出

本轮全文与分析成功后，计划页面会出现“本轮比较与综述”。研究问题默认取本轮计划的问题，比较维度默认取计划中的维度，均可修改后确认。
“查看本轮比较矩阵”固定使用该轮已保存的 paper_id/analysis_id，展示五类分析及原文引用；确认的比较维度供综述进行重点对照，不会自动编造新的实验指标表。
“确认问题并生成本轮综述”依次核对版本、生成比较、撰写详细综述并核验跨论文引用。只有通过核验才发布报告，页面可导出 Markdown、比较矩阵 CSV、JSON，或打开独立综述页面。
快速/部分阅读的覆盖说明同时送入模型、显示在计划页面并附在 Markdown 导出中；未读内容不能当作缺失实验或论文局限。
报告独立保存计划版本、执行编号、人工确认的问题、维度、论文和分析编号。修改计划不会改变历史报告；切换研究问题生成新记录，相同已成功输入复用报告。
失败保留比较矩阵与单篇分析，使用相同问题和维度再次生成会重试报告；服务重启中断后也可继续，已有核验成功的子报告可恢复，不重跑论文分析。
报告完成表示可导出，浏览器实际下载是否保存不由服务端冒充确认。真实网络和模型生成仍需在本机验收。
